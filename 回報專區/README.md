# 回報專區

學生（使用者）回報的問題集中貼在這裡處理。每一則問題一個檔案，處理完會附上**官方回覆**與**補償建議**。

## 怎麼用

1. 把學生的原始訊息（文字、截圖描述、時間、群組名稱）貼給 Claude，或複製 `_範本.md` 另存成新檔。
2. Claude 會依下方流程處理，結果寫回同一個檔案。
3. 你確認官方回覆與補償內容後，再由官方帳號回覆學生。

檔名格式：`YYYY-MM-DD_簡短標題.md`，例如 `2026-09-25_沒收到備份.md`

## 處理流程

| 步驟 | 內容 |
|---|---|
| 1. 整理資訊 | 誰、哪個群組、什麼時間、預期看到什麼、實際發生什麼 |
| 2. 確認資訊 | 對照程式（`index.js`）與 LINE 官方限制，判斷是 **Bot 問題**、**使用方式問題**、還是 **LINE 限制**；資訊不足就列出要向學生補問的問題 |
| 3. 解決 | Bot 問題 → 修程式並 commit；使用方式 → 寫清楚操作步驟；LINE 限制 → 說明原因與替代做法 |
| 4. 官方回覆 | 可直接貼給學生的訊息：先致歉/感謝 → 原因（白話）→ 已做的處理 → 學生需要做什麼 |
| 5. 補償建議 | 依下方級距提出，最後由你決定是否採用 |

## 常見原因速查（先對照這裡）

| 症狀 | 常見原因 | 對應處理 |
|---|---|---|
| 完全沒收到備份 | 沒加 Bot 好友 / 輸入過 `!停用` | 請學生加好友、輸入 `!設定` 確認狀態 |
| 沒收到 @All 備份 | 輸入過 `!全體關`，或 Bot 還沒「見過」這位學生（沒發言、沒被 tag） | 輸入 `!全體開`；請學生在群組發言一次 |
| 漏了某些訊息 | Bot 加入群組前的訊息、非文字訊息（圖片/貼圖）不會記錄 | LINE 限制，說明即可 |
| 卡片只顯示 15 則 | 單張卡片上限 15 則 | 說明；可改用 `!合併` 分批收 |
| 當天沒寄出 | 本月推播額度用完（`!額度` 可查）、伺服器休眠或重啟 | 查額度與伺服器紀錄 |
| 備份內容消失 | 未設定 JSONBin，伺服器重啟後本機資料遺失；寄送失敗時也會清空待寄資料 | Bot 問題，需修正／設定雲端儲存 |

## 補償建議級距

| 等級 | 影響 | 建議補償 |
|---|---|---|
| A 輕微 | 使用方式問題、LINE 限制，學生沒有實際損失 | 誠懇說明＋操作教學，不需補償 |
| B 一般 | Bot 問題造成延遲或少量漏寄，事後可補救 | 致歉＋協助補寄/整理漏掉的訊息 |
| C 明顯 | Bot 問題導致學生錯過重要通知（作業、課程、考試資訊） | 致歉＋補寄＋由老師/班務主動補充錯過的內容；影響作業繳交時建議延長期限或不扣分 |
| D 嚴重 | 多人受影響或造成實際權益損失（缺課、缺考、成績受影響） | 正式致歉公告＋個別聯繫＋補課/補考或等值補償（由行政決定） |

> 補償只是建議，實際內容以班務/行政決定為準。同一原因影響多位學生時，補償標準要一致。
